# 作品自动标签与匹配证据链设计

## 背景

当前智能推荐已经能根据创作者简介、风格和工具给应征者打分，但还没有真正把“作品集”纳入匹配依据。用户点击推荐卡片后，也只能看到简介、风格、工具等资料，无法直接看到“系统为什么认为这些作品匹配当前需求”。

本阶段补齐作品自动标签和匹配证据链，让“依据上传作品生成能力标签，并匹配相关创作者作品”成为可演示、可测试的功能。

## 目标

- 根据创作者简介、风格、工具、作品标题和作品描述生成能力标签。
- 为每个作品生成作品标签。
- 智能匹配结果包含命中标签、命中作品、推荐理由。
- 项目详情的智能推荐卡片显示命中标签。
- 点击应征者卡片后，弹窗展示匹配作品和命中原因。
- 没有真实 AI API 时，仍通过规则 fallback 稳定运行。

## 非目标

- 不做真实图片视觉识别。
- 不接新的多模态 API。
- 不改上传作品的完整流程。
- 不重构创作者认证页。

## 数据模型

新增服务 `creatorTaggingService`，导出：

- `PortfolioTagResult`
- `CreatorCapabilityProfile`
- `tagPortfolioItem(item, context)`
- `buildCreatorCapabilityProfile(input)`

标签来源分三类：

- 创作者资料：`bio`、`styles`、`tools`
- 作品文本：`title`、`description`
- 项目关键词：需求描述和分类

标签会去重，并保留常见能力词，如：

- 科幻、赛博朋克、国风、二次元、写实、产品宣传、品牌宣传、短片、动态影像、角色、场景、分镜、剪辑、Runway、Kling、ComfyUI、Midjourney、Stable Diffusion

## 匹配结果

升级 `matchApplicants` 返回结构：

```ts
{
  id: string;
  score: number;
  matchedTags: string[];
  matchedPortfolioIds: string[];
  reasons: string[];
}
```

旧调用只使用 `score` 时仍可工作。

匹配逻辑：

1. 将需求描述和分类转成关键词集合。
2. 为每位创作者构建能力画像。
3. 匹配命中标签。
4. 找出命中标签最多的作品。
5. 计算分数并生成理由。
6. DeepSeek 失败或返回不合法时，使用规则结果。

## 页面体验

项目详情智能推荐区：

- 卡片增加最多 3 个命中标签。
- 智能推荐解释弹窗增加“匹配作品”区域。
- 如果有匹配作品，展示作品图、标题、描述、命中标签。
- 如果没有匹配作品，展示当前已有的简介、风格、工具理由。

## 错误处理

- 作品集为空时仍可根据简介、风格、工具打分。
- AI 返回缺少证据字段时，用规则证据补齐。
- 作品图片加载失败不影响推荐分数展示。

## 测试策略

- `creatorTaggingService`：测试作品标签、能力画像、去重。
- `aiService`：测试 fallback 匹配包含命中标签、命中作品、推荐理由。
- `useSmartMatch`：测试 hook 能透传扩展匹配结构。
- 构建与浏览器 smoke test：项目详情中推荐卡片和解释弹窗可渲染。
